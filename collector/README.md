# collector

Python/httpx/Jinja2/HTMX-сервис: адаптеры источников, нормализация, доставка
в Core API, веб-страницы. Порт **8001**. Реализует ФТ-1.1–1.8, НФТ-3, НФТ-15.

Формат `RawListing` и контракт доставки — [docs/contracts.md](../docs/contracts.md)
§1 и §3; внешний источник (ТЗ 4.6) — сервер mock-avito (PR #62), collector
без парсинга HTML.

## Что внутри

- **Адаптеры** (`app/adapters/`) — общий интерфейс `fetch() → list[RawListing]`:
  `MockAdapter` (локальный дамп + stream-генерация) и `AvitoApiAdapter`
  (внешний API; схема ответа совместима с mock-avito, скрыта пагинация).
- **Нормализация** (`app/normalize.py`) — `price_usd` через курсы Core API
  (Decimal, `ROUND_HALF_UP` до целого USD), очистка HTML, комнаты
  (студия=0), площадь ≤2 знаков, канонизация городов по справочникам;
  некорректные записи пропускаются с причиной в логе и реестре запусков.
- **Доставка** (`app/publisher.py`) — `POST /api/v1/listings`: начальная
  попытка + до 5 повторов при сети/429/5xx, экспоненциальная задержка
  1–30 с с учётом `Retry-After`; прочие 4xx не повторяются, после исчерпания
  попыток запись остаётся доступной для повторного запуска (ФТ-1.6).
- **Дедуп** (`app/dedup.py`) — Redis до отправки; хэш помечается
  обработанным только после 200/201; Redis недоступен — отправка
  продолжается через идемпотентный API (ФТ-1.5, НФТ-7).
- **Оркестрация** (`app/runner.py`) — пакетный сбор по расписанию
  (`COLLECT_INTERVAL_SECONDS`, 15 мин по умолчанию) и stream-режим mock
  (запись раз в 5–30 с, `MOCK_PUBLISH_MODE=stream`); параллельные циклы
  одного источника не допускаются (ФТ-1.4).
- **Админ-эндпоинты** (`app/admin.py`) — `POST /collect/run` (202 + `run_id`,
  409 при активном запуске) и `GET /collect/runs/{run_id}` под
  `X-Admin-Key` (НФТ-3). Пустой `ADMIN_KEY` открывает доступ — dev-режим
  с предупреждением в логе (как у `/debug/event` в notifier).
- **UI** (`app/ui.py`, `templates/`) — две страницы Jinja2+HTMX (НФТ-15):
  список с фильтрами и карточка со ссылкой на источник; данные только
  через Core API, для `source=mock` — явная отметка о синтетических данных.
- **Health** (`app/health.py`) — `/health` (живость) и `/health/ready`
  (Core API + Redis; справочники отражаются в ответе, но готовность
  не валят).

## Промежуточный режим: справочники ФТ-2.4 ещё не смержены

`price_usd = price × rate_to_usd` требует курсов Core API, а канонизация
городов — справочника городов. Пока ФТ-2.4 не влит:

- записи в **USD** идут без справочников (USD=1 задан контрактом);
- **не-USD** записи пропускаются с причиной «курсы недоступны»;
- города/страны проверяются только по формату, канонизация недоступна.

После мержа ФТ-2.4 (эндпоинты и форматы уже описаны в contracts.md §3)
код менять не нужно — `app/dicts.py` подхватит справочники сам, полные
проверки включатся автоматически. Синхронизацию наборов mock-данных со
справочниками можно добавить интеграционным тестом (как в mock-avito).

## Запуск

```bash
# в составе стенда (из корня репо)
docker compose up --build

# локально, без docker
cd collector
python -m uvicorn app.main:app --port 8001
```

Переменные окружения — см. `.env.example` в корне репо
(`MOCK_MODE`, `MOCK_PUBLISH_MODE`, `MOCK_DUMP_PATH`, `MOCK_STREAM_*`,
`COLLECT_INTERVAL_SECONDS`, `SOURCE_API_URL/TOKEN`, `ADMIN_KEY`,
`CORE_API_URL`, `REDIS_URL`).

Демонстрационный дамп `data/mock_dump.json` — ~30 записей, включая
намеренно некорректные (нулевая цена, неизвестный deal_type, город
написанием «Минск») — чтобы были видны и пропуск с причиной, и будущая
канонизация. Полный синтетический дамп ≥500 объектов / ≥5 стран / ≥10
городов (contracts.md §3) отдаёт mock-avito (PR #62); для локального
запуска collector'а его можно положить в `data/mock_dump.json` или
указать через `MOCK_DUMP_PATH`.

## Тесты

```bash
cd collector && python -m pytest -v
```

Без сети и БД: httpx.MockTransport для Core API/источника, fake-Redis.
CI (python-ci) уже включает collector в матрицу ruff+pytest.

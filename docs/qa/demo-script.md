# Демо-сценарий сдачи (черновик Даниила; порядок показа согласуется с командой)

Базируется на протоколе приёмки (`docs/qa/e2e-protocol.md`) — демонстрируем то, что уже принято протоколом. Целевая длительность: 10–15 минут.

## До демонстрации (подготовка, ~10 минут)

1. `docker compose up --build` (профиль `--profile mock`, когда смержен #62) — все сервисы healthy.
2. Telegram на большом экране (или log-режим в терминале — оговорить заранее).
3. Стенд прогрет: дамп 500+ загружен (`POST /collect/run`), кэш прогрет одним GET.

## Запасные ответы на вопросы комиссии

- **Почему не exactly-once Telegram?** ТЗ 3.5/4.3 прямо: сбой «ответ Telegram без записи» → unknown, автоповтор запрещён (contracts.md §2); дедуп на (user, listing) в БД.
- **Почему outbox, а не XADD в ручке?** ФТ-2.5: атомарность «запись + задание», ошибка Redis не теряет событие (ТЗ 4.3).
- **Что происходит при падении Postgres?** Демо-S7 протокола: события остаются в pending (PR #68), после восстановления доставляются ровно один раз.
- **Эквивалентность замеров:** машина/состав данных/фильтры фиксируются в отчёте (НФТ-10/11) — приложить отчёт из протокола.
